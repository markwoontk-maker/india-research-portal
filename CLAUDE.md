# India Research Portal — project notes

## Hosting & deploy
- **Static GitHub Pages site.** Public repo `markwoontk-maker/india-research-portal`, branch `main`. Pushing to `main` auto-publishes — no build minutes, no credits, nothing to babysit.
- Live URL: https://markwoontk-maker.github.io/india-research-portal/ (project subpath `/india-research-portal/`).
- `.nojekyll` at repo root so files serve as-is.
- **Netlify path is deprecated/blocked** (free build-minute cap kept failing deploys). The `netlify/functions/*` + `netlify.toml` are kept only as optional server proxies; do not rely on them.
- Single self-contained `index.html` (inline CSS/JS); Chart.js + Google Fonts via CDN. No build step.
- **Always commit + push on any dashboard change** (the user expects the live site updated every time).
- **Pages sometimes skips a build.** When commits land close together (or right after an `errored` build), GitHub Pages occasionally never queues a build for the newest commit, so a successful `git push` doesn't go live — `gh api repos/markwoontk-maker/india-research-portal/pages/builds/latest` shows the last built commit lagging `origin/main`. Force a rebuild with `gh api -X POST repos/markwoontk-maker/india-research-portal/pages/builds`, then poll `.../pages/builds/latest` until `status:built`. If a change "isn't reflected on the site" despite a good push, check this first (build `build_type` is `legacy`, source branch `main`).

## India Macro Snapshot card (News/Markets tab)
- **Now three CLSA momentum heatmaps** (replaced the old broker-row table 2026-07-07), all inline in `index.html`: `MACRO_TABLES` (data), `MACRO_MONTHS`, `macroNum()`, `macroCellClass()`, `renderMacroTables()`, `loadMacro()` (just calls the renderer). Tables: (1) *Indicators used to create India's EAI for real GVA growth* (CLSA Fig 11, with section headers Agriculture/Industrial/Services/Aggregates + bold sub-total rows via `k:'tot'`/`k:'sec'`), (2) *consumption spending*, (3) *investment activity*. Layout: indicators down a **sticky left column**, months (`May-25…May-26`) across a sticky top header, each table in its own `.macro-wrap` (horizontal + vertical scroll, `max-height:74vh`), tight rows.
- **Numbers are transcribed verbatim from the CLSA exhibits — never recomputed.** Each row = `{n, k?, v:[13 strings], c:'13-char colour code'}`.
- **Cell colour is DERIVED (4-colour momentum scheme), not copied from the source palette.** `macroCellClass()`: the **MoM** half is computed from the series (`v[i] >= v[i-1]`, higher = better; first column falls back to the `c` code), the **YoY** half is read from the source cell's colour family encoded in `c` (`g`/`y` = better YoY, `o`/`r` = worse YoY). Result classes: `mc-r` RED (worse MoM & YoY), `mc-y` YELLOW (worse MoM, better YoY), `mc-o` ORANGE (better MoM, worse YoY = the source's blue), `mc-g` GREEN (better MoM & YoY). CSS `.heat-tbl`/`.mc-*`/`.macro-legend`. **Known caveat:** the YoY dimension was eye-read from the images, so ORANGE (rising-but-below-year-ago) is likely under-represented vs the source — to correct a cell, flip one char in that row's `c` string (only its `g/y` vs `o/r` family matters; MoM is auto-computed).
- **Legacy (unused, pending removal):** the old `MACRO_REPORTS` array + `MACRO_LIVE`, `applyMacroOverlay()`, `data/macro.json` overlay, drag-to-reorder, and the `docs/macro-refresher-prompt.md` data.gov.in routine plan are now DEAD (kept in the file for now, not wired to `loadMacro`). Don't build the macro-refresher routine against them.

## Earnings Calendar card (News/Markets tab)
- `#earnCal` / `loadEarnCal()` / `renderEarnCal()` — next **7 business days** (Mon–Sat, `bizDays(7)`) as **side-by-side day columns** (`.earn-cal` is a horizontally-scrolling flex row; `.ec-day` ~198px each), today's column flagged `.today`. Each column is a 3-across `.ecal-grid` of square tiles.
- **Rows (`.ecal-list`/`.ecal-item`):** one row per company = **name + YTD return** (no logos — the feed has none). Capped at `EC_CAP=12`; the trailing **"+N more" / "show less"** toggles that day in place (`ecExpanded` set + delegated click/keydown handler on `#earnCal`, re-renders from cached `ecItems`).
- **Coverage = the Watchlist tab** (NOT companies.json/NOTEBOOKS). `ecWatch()` maps the live `WL` object (`hold`+`cov`+`watch`, incl. localStorage edits) `ecKey(name) -> {name, sym}`; `ecMatch()` matches a calendar item by full name or short name. Covered names sort to the top of each day, highlighted (`.ecal-item.mine`); the day header shows `N co. · M covered`. Within **both** the covered and non-covered groups, rows sort by **YTD descending** (unpriced names last), so the visible top-`EC_CAP` per day are the best performers.
- **YTD source:** live Yahoo for **every** row (not just covered), fetched once by `ecFetchYtd()` via the Watchlist tab's helpers (`sparkR`/`pctOver`/`pick`/`chunk`, `TF['YTD']`), keyed by primary NSE symbol in `ecYtd`, then re-renders. Idempotent (`ecYtdDone` guard), cached, never blocks the calendar; rows show `—` until priced (or permanently for BSE-only names). `ecSym(wl,it)` picks the symbol: the curated watchlist symbol if covered, else `item.sym`. (`renderEarnCal` calls `ecFetchYtd` at the end; the guard prevents render↔fetch recursion.)
- **`item.sym`** (Yahoo `SYMBOL.NS`) is resolved **server-side** in the refresher via `fetchNseSymbolMap()` — NSE's `EQUITY_L.csv` equity master, matched by `nkey()` (same normalisation as `ecKey`), EQ/BE series only. ~482/720 match; the misses are BSE-only microcaps with no NSE line (they render without a YTD). Best-effort: CSV fetch failure just omits symbols, calendar still ships.
- **Coverage matching is by SYMBOL first, then name** (`ecMatch` + `ecWatch` returns `{byName, bySym}`). ICICI writes full registered names ("Syrma SGS Technology Ltd") that don't `ecKey`-match the watchlist's short names ("Syrma SGS"), but the refresher-tagged `item.sym` equals the watchlist symbol (`SYRMA.NS`), so symbol equality is the reliable key. `bySym` includes each pipe-separated fallback symbol.
- **GOTCHA — fetch day-by-day, never a wide range.** ICICI's `Get_EquityCompanyEvents` **caps a wide `P_FROM_DATE..P_TO_DATE` query server-side and silently drops companies** (a busy day comes back partial — Syrma SGS was missing, 29 Jul returned 81 of 109). The refresher sets `P_FROM_DATE == P_TO_DATE` and loops each day (skipping Sundays), paginating within the day; a single-day query is complete. Verified file count == live API count for every date. Do NOT collapse this back into one range call to save requests.
- **Class naming:** the calendar uses `ecal-*`; `.ec-co`/`.ec-tk` belong to the earnings **news** feed (`fmtEarnFeed`). They previously collided — don't reintroduce `.ec-co` in the calendar.
- **Not available from this source:** a Before Open / After Close split. Indian board-meeting intimations carry no session field — don't fabricate one.
- **Data: committed `data/earnings_calendar.json`** `{asOf, source, sourceUrl, from, to, items:[{date:"YYYY-MM-DD", name, short}]}`, a rolling **35-day** forward window. `loadEarnCal()` reads this first; the old `/api/earncal` (BSE) is kept only as a fallback for the dead Netlify path.
- **Source: ICICI Direct results calendar** (`https://www.icicidirect.com/share-market-today/company-results`). The page is an SPA; its data comes from `POST https://www.icicidirect.com/marketapi/market` with `Method=Get_EquityCompanyEvents` + `param[i][key|value]` pairs (`P_FROM_DATE`/`P_TO_DATE` as `yyyy-Mon-dd`, `p_pagenumber`, `p_pagesize`), returning `{Data:{Table:[{EVENTTYPE,EVENTDATE:"Jul 31, 2026",CO_NAME,LNAME,CO_CODE,RESULT_NOTE}]}}`.
- **Why it can't be fetched client-side (don't retry this):** the response sets `access-control-allow-origin: https://www.icicidirect.com`, so a browser on Pages is blocked; and the endpoint **ignores query-string params** (a GET returns `Table:[]`) so the GET-only public proxies (codetabs/allorigins) can't forward it either. Hence the local refresher.
- **Refresher (LOCAL):** `scripts/refresh-earnings-calendar.js`, step **8b3** in `daily-refresh.ps1` (which stages/commits/pushes `data/earnings_calendar.json`). Results-only (`EVENTTYPE=Result`), deduped by date+name, paginated at 500/page. Rewrites the whole file each run, but **keeps the last good file** if the fetch fails or returns nothing; never throws. Same local-only reason as FII/DII (cloud routines can't push this repo).
- **Coverage highlighting:** `ecCoverage()` builds a normalised key set from `window.COMPANIES` + `NOTEBOOKS`; `ecKey()` lowercases, strips non-alphanumerics and a trailing `ltd`/`limited` so "Adani Power Ltd" matches "Adani Power". Covered names sort to the front of each day, render with `.ec-co b.mine` (saffron), and the day header shows `N co. · M covered`. Chips cap at `EC_CAP=60` with a `+N more` tail (peak season runs ~50–56 companies/day).

## Positioning tab (FII/DII daily flows)
- Sidebar tab **Positioning** (`data-view="positioning"`, `#viewPositioning`). Two stacked cards — **Net FII Flows** and **Net DII Flows** — each a Chart.js combo: daily net **bars** (green +/red −, left axis) + running **cumulative line** (saffron, right axis). - **Period selector** (`#posSeg`, `.seg` on the FII card header): **MTD · QTD · YTD · All** (`posFilter()`, anchored on the latest data date). - Data: committed **`data/fii_dii.json`** — ascending array of `{date:"YYYY-MM-DD", fii_net, dii_net}` (NSE/BSE **provisional cash-market net**, ₹ Cr, signed), daily since **1 Jan 2026**. The page derives the cumulative client-side. No live fetch (FII/DII is a once-daily post-close print).
- **Data-source provenance (important):** backfilled from `fatafatniftylevels.in/fii-dii.php` — the only free source found with a complete, *correct* daily series back to 1 Jan. It matches Groww (the reference) and NSE-published daily + monthly figures exactly (e.g. 2 Mar 2026 = FII −3295.64 / DII +8593.87; March total ≈ FII −1.22L cr / DII +1.43L cr vs reported −1.18L / +1.16L). **`MrChartist/fii-dii-data` was rejected** — its Jan–Mar values are wrong (disagreed on 49/78 overlapping days) and it has large gaps. Do **not** swap the source or "correct" historical rows without re-verifying against NSE-published figures.
- **Refresher (LOCAL):** appended daily by `scripts/refresh-fii-dii.js`, a step in `scripts/daily-refresh.ps1` AND the standalone weekday-09:00 "India FII-DII Refresh" task (both commit+push). **Two sources, merged:** (1) fatafatniftylevels (needs `Accept`/`Accept-Language` headers or it 502s), then (2) **Groww fallback** (`groww.in/fii-dii-data`, server-rendered `<td>` table: `date | FIIbuy | FIIsell | FIInet | DIIbuy | DIIsell | DIInet`, date `"03 Aug 2026"`). Fatafat's value wins on shared dates; Groww only fills days fatafat is missing — added 2026-08-04 because **fatafat routinely lags a full trading day** (it sat on 31 Jul while Groww/Trendlyne already had 03 Aug, freezing the chart). If the two disagree >1 cr on a shared date it logs a warning and keeps fatafat. Append-only, idempotent, never throws. **The cloud routine `trig_01Y9QCbBV86F1GGa4eJiWF1g` was DISABLED** — it fired daily but its `git push` silently failed (the CCR env clones the public repo read-only / no write token), so its appends never reached GitHub. **General gotcha: remote CCR routines can't push to this repo** — anything that must commit has to run from the local pipeline (or deliver via Gmail draft, like the research refresher). ## Watchlist tab — Daily Return chart + per-stock contribution
- The **Portfolio Daily Return** card (`#wlDailyCard`, `wlRenderDaily()`) is a Chart.js combo, one column per settled trading day, period selector (`#wlDailySeg`), **Recompute** button (`#wlDailyReset`). **Four series on two y-axes:** LEFT axis `y` = **WR return (daily)** green bar + **Nifty 500 (daily)** teal bar (both ~±1%); RIGHT axis `y1` ("cumulative %") = **Cumulative (WR relative, compounded)** purple line (compounds daily `WR−index`) + **Cumulative (WR portfolio, compounded)** blue line (compounds daily WR). "WR" = weighted returns. The two y-axes share an aligned **zero line** (`zAxisAlign()` inside `wlRenderDaily`, mirrors the Positioning tab's `posZeroAlign()`). Custom **check-box legend** (`#wlDailyLegend`, `wlBuildDailyLegend()`) toggles each series; state persists in `irp_daily_vis_v1`. Legend keys are the dataset labels, so renaming a series resets its saved on/off to visible.
- **Data source = exact official NSE, NOT Yahoo.** Committed `data/wl_returns.json` = `{updated, dates:{ 'YYYY-MM-DD': { index:<Nifty500 %chg>, r:{ <NSE_SYMBOL>: <close-to-close %> }, c:{ <NSE_SYMBOL>: <absolute close> } } }}`. `c` (closes) drive the market-value weights; `r` (returns) drive the per-stock contribution. Built from the NSE **daily bhavcopy** (`nsearchives.nseindia.com/products/content/sec_bhavdata_full_<DDMMYYYY>.csv`, return = `CLOSE_PRICE/PREV_CLOSE-1`) + **index close** (`.../content/indices/ind_close_all_<DDMMYYYY>.csv`, Nifty 500 `Change(%)`). NSE is the source because it has an exact close for **every** stock — including the names Yahoo silently drops daily (Emcure, KEI, Hero, Torrent, Lincoln, and `GVT&D` with the ampersand). Keys are the bare NSE symbol; the client strips `.NS`/`.BO` (`wlNseSym()`) to match, and reads the index from `.index`.
- **Why committed, not fetched live:** a static Pages site can't reach NSE from the browser (no CORS) and **both public proxies are dead** (corsproxy.io now 403s non-localhost; allorigins 522s). So returns are fetched **server-side** by `scripts/refresh-wl-returns.js` and committed. Same push gotcha as FII/DII — must run from the LOCAL pipeline, never a cloud routine.
- **Refresher:** `scripts/refresh-wl-returns.js` (Node, no deps) — append-only + idempotent, **floored at `START_FLOOR='2026-07-14'`** (the chart does not backdate before this), `LOOKBACK_DAYS=14` to fill any missed weekday; a 404 = weekend/holiday and is skipped; never throws. Wired as step **8b2** of `daily-refresh.ps1` (weekday **09:30**, "India Research Portal Daily Refresh"), and `data/wl_returns.json` is in that script's `git add` list so it commits + pushes each morning. To change the display floor, edit `START_FLOOR` (and re-seed).
- **Return = market-value weighted (quantity-based), START-OF-DAY weights.** `wlPortfolioReturnOn(D)` returns `{p}` = the day's change in TOTAL MARKET VALUE of fixed quantities: `p = (ΣMV_D / ΣMV_{D-1} − 1)·100 = Σ(start-of-day weight × stock return)`, where `MVᵢ = qtyᵢ × close` and start-of-day weight = `qtyᵢ×close_{D-1} / ΣMV_{D-1}` (the PREVIOUS close). This is the exact, unbiased money-return and the professional standard (GIPS time-weighted). Prev close = the previous file date's `c`, or for the floor date derived as `c/(1+r/100)`. (A same-day-weight variant matching the user's `2026.xlsx` col BD was tried 2026-07-24 but reverted — it over-weights that day's winners, biasing returns up ~1–5 bps/day.) **Quantities** live in `wlEntry[sym].qty` (localStorage `irp_entries_v1`) — user-entered, **never committed** (personal position sizes; public repo). Current Holdings shows a **Qty input** (`.wl-qty`) with an auto-derived read-only **Weight** (`.wl-wt` = qty×live-LTP/total, `wlHoldWt()`/`wlHoldMVTotal()`, Total row ≈ 100%). `wlContrib[D]` = each holding's `{w, r, contrib:w·r/100}` for the hover tooltip, summing to `p`. The old `sp`/`wa` (sum-product / weighted-average) bases were removed 2026-07-24. **Quantities** live in `wlEntry[sym].qty` (localStorage `irp_entries_v1`) — user-entered, **never committed** (personal position sizes; public repo). The old `sp`/`wa` (sum-product / weighted-average) bases were removed 2026-07-24 — with proper MV weights they collapse to this single correct return.
- `wlCaptureDaily()` stores `{p, i, contrib}` per date (`wlDayP`/`wlDayI`) and is **FROZEN**: a settled day, once recorded, is never rewritten (only new settled days are added). **Cumulative WR portfolio** = compound `p` (= sheet col BG); **Cumulative WR relative** = `cumPort − cumIndex` (difference of the two compounded curves, = sheet col BI). Store key `WL_DAILY_LS` (currently `irp_daily_returns_v11`) is bumped on formula/schema changes — but NOT for the transaction-wiring change (bumping would recompute frozen days at CURRENT quantities and corrupt history, since qty is a single snapshot, not a per-date ledger). The **Recompute** button (`#wlDailyReset`) rebuilds ALL days at current quantities and now **confirms first** — dangerous after any qty change.
- **Portfolio Transactions FEED the return (re-wired 2026-07-28), adjusting ONLY the day they settle.** In `wlPortfolioReturnOn(D)`, start-of-day qty is reconstructed as `current_qty − buys_on_D + sells_on_D`; a **BUY** leg (entry date D, price `ep`) adds `qty×(close_D − ep)`, a **SELL** leg (exit date D, price `xp`) adds `qty×(xp − close_prev)` and removes those shares from close-to-close; everything else earns close-to-close. `port = ΣP&L / Σ(startQ×close_prev)`. With no trades it reduces to the plain start-of-day money-return. Traded names get a `*` in the hover breakdown. Editing a transaction **surgically unfreezes only its `ed`/`xd` dates** (`recompute` in `wlTxnsInit` deletes those from `wlDailyReturns` then re-captures), preserving other frozen days. **Workflow after a trade:** update the Qty in Current Holdings to the post-trade quantity AND log the buy/sell in Portfolio Transactions on its date — the reconstruction needs both. `wlFillGaps`/`wlFillIntraday`/`wlDayWA` are unused (left in place, harmless).
